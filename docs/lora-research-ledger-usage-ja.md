# LoRA研究台帳の使い方

PySide6のデスクトップアプリです。元ログ・画像・重みを現在の場所へ残し、参照と人間の評価を外部フォルダへ保存します。

## 起動

sd-scripts直下の **lora_ledger_gui.bat** をダブルクリックします。リポジトリのvenvがあればそのPythonを使います。PySide6以外の追加パッケージやGPUは必要ありません。

```powershell
.\venv\Scripts\python.exe lora_ledger_gui.py
```

初回は「新規台帳」でリポジトリ外の空フォルダを選びます。既存台帳は「台帳を開く」でledger.jsonがあるフォルダを選んでください。前回の台帳が見つからない場合、勝手に空の台帳へ置き換えません。

## 普段使う操作

1. 左の一覧で学習を選びます。現在名、旧名、設定、メモで検索できます。
2. 右の「評価する対象」で、特定のcheckpointか「学習全体の印象」を選びます。
3. 星、学習の目的、良いところ、悪いところ、任意メモを必要な分だけ入力します。
4. 「保存」またはCtrl+Sで保存します。

5項目はすべて任意です。星は空欄と★1を区別します。「学習の目的」だけでも保存でき、空の評価イベントを作りません。

目的・経緯は学習全体の記録です。他の4項目は選択した評価対象だけに付きます。epoch10の評価がfinalへコピーされることはありません。複数対象を評価すると一覧は「複数評価」と表示します。

「保存」は訂正として旧版を残します。「新しく見直した評価として保存」は元の評価と結び付けた別の評価を作り、通常の集計では重複票にしません。履歴は「評価の履歴」で確認できます。

「当時の評価を登録」「記憶から登録」を選ぶと背景も残ります。当時の正確な日付を記録していない評価にはoriginal_date_unknownが付きます。

## データセット名と日時順の表示

データセット名は、記録されたdataset_configのTOMLファイル名を優先します。設定記録とcheckpointメタ情報が対象です。TOML名がない場合はメタ情報のフォルダ名を使い、空の名前や重複回避の「(2)」しかない場合は「名称不明（6サブセット）」などと表示します。学習設定全体のconfig_fileをデータセットのTOML名と推定することはありません。

右側の「データセット」欄を編集すると「手動名を優先」に切り替わります。「保存」すると、再走査で自動取得情報が増えても手入力を保持します。「自動取得に戻す」で記録由来の名前へ戻せます。表示名は内容の同一性を証明するものではありません。

左側の「並び順」で「日時（新しい順）」「日時（古い順）」を選べます。「学習日時」の列見出しを押しても並べ替えられます。

日時は学習開始のメタ情報・設定記録を優先します。不明なら、参照できるfinalのチェックポイント更新日時を優先し、finalがなければ他の重みの最新更新日時を代用します。元ファイルが失われている場合は最後に記録した更新日時を使います。日時不明は昇順・降順とも最後です。台帳へ登録した日時は学習日時に代用しません。

日時の列にマウスを重ねると出典と対象ファイルを確認できます。表示は端末のローカル時刻です。CSVとAI相談用出力にも日時・出典、TOMLの記録パスを含めます。

既存台帳の表示は新しいGUIを起動すると反映されます。自動表示の更新で手入力や評価を変更しません。

## ログの場所と再走査

「参照先の設定」でフォルダを追加します。各行の有効・子フォルダの探索・除外フォルダを指定できます。

学習出力の親フォルダを1行だけ指定すれば、直下の重み・ログに加えてrun_records、diagnostic_report、dq_dataset_profilerも調べます。例えば `D:\lora-workspace\lora_output` のような配置です（架空の例）。画像比較が別の場所なら、そのフォルダも追加します。

新たな学習やレポート生成の後は「再走査」を押します。

- **新しい学習**：登録する新しい学習候補。
- **追加資料あり**：登録済みの学習に新たな重み・ログ・レポートがある。
- **変更あり・要確認**：以前のファイルが上書きされた、または見つからない。内容を確認して反映対象にチェックする。
- **登録済み**：変化なし。既定では差分表から隠す。
- **関連資料のみ**：学習と結び付いていないデータセット診断・画像比較等。

新規と追加資料が既定の反映対象です。走査と反映の間にファイルや台帳が変わった場合、その項目を保留します。途中で中止しても保存済みの評価は残ります。

フォルダ全体が接続できない場合は「参照先にアクセスできない」として報告します。全件を削除扱いにしません。その参照先の登録内容を保持したまま、接続できる別の参照先にある新しい重み・資料は反映できます。フォルダを移動したときは「場所を変更」で対応を更新できます。親と子を重ねて登録しても同じファイルを二重に列挙しません。

通常の再走査はサイズ・更新時刻とキャッシュを利用します。サイズと時刻を保ったまま内容を変更した場合の確認には、内容hashの再確認が必要です。

## 旧checkpoint、改名、上書き

学習設定ファイルがない場合、safetensorsのヘッダーから記録済みの設定を取得します。未記録の設定は現在の既定値で補いません。

現在のファイル名を基本表示に使い、内部のss_output_nameは旧名として検索できます。ファイル名と内部名が違っても、その重み自身のメタ情報を読みます。

学習の対応にはsession IDと開始時刻等を使います。同じ名前の別sessionを結合しません。名前だけで推測したログは「対応未確認」です。「元ログ・レポート」で資料を選び、「選択資料はこの学習のもの」で人が確認した対応を記録できます。複数行を選んでまとめて確認することもできます。

上書きを検出した場合は古い成果物・評価を残し、新しい成果物として扱います。すでに失われた上書き前の設定を、現在の重みから復元したことにはしません。

メタ情報だけで同一内容を断定できない改名・コピーは、別の成果物として残る場合があります。旧参照に内容hashがある場合、完全確認を伴う走査で同一内容を見つけられます。

## 比較の判断を残す

「比較の判断を記録」を開き、比較レポートのフォルダを取り込むか、重みから候補を追加します。

画像比較レポートはmetadata.jsonと任意のconfig.jsonを読みます。生成に成功して画像が残るケースを対象にし、失敗した候補を勝敗に混ぜません。古い保存パスが台帳と一致しない場合は「選択候補の重みを対応付け」で指定できます。未対応のままでも、その状態を明記して記録できます。

強度とLBWは「選択候補の強度・LBWを編集」で設定します。強度は共通の1値、TE・UNetの2値、TE1・TE2・UNetの3値をカンマ区切りで入力できます。不明なら空欄にします。複数LoRAのレポートは構成全体を1候補として保持します。

実際に見た候補へチェックし、必要な判断だけ入力します。

- 総合の第一候補、本人らしさ、顔・人体の自然さと理由。
- 候補ごとの単独の実用性。
- 実際に採用した候補、採用なし、未決定。
- 用途、記憶による評価か、全ケースか一部か、名前を伏せたか。

A・B・Cを見てBを第一候補にした場合、記録する比較はB>A、B>Cだけです。AとCの順位は付けません。同程度、判断保留、未評価も別に扱います。「使えるけれど別の候補を採用した」も保存できます。

保存時の重み確認は評価対象だけを読みます。今回読んだファイルのhashが、過去の画像生成時の重みと同じだったことまでは証明しません。その状態は評価・分析出力に残ります。

比較評価の訂正・再評価は「評価の履歴」内のボタンから開けます。保存済みの対象promptと閲覧ケースは再編集時にも保持します。取り込んだケース一覧も保持するため、対象promptの追加・変更や全ケースへの切り替えができます。以前の版で保存した部分評価を広げる場合は、元の比較レポートを参照します。レポートの欠落・変更や存在しないpromptは、保存せずに通知します。

## ExcelとAIへの出力

「CSVを書き出す」では、表示中の学習について一覧・評価詳細・全履歴を選びます。一覧は列を選べ、学習の並び順を反映します。日本語向けUTF-8 BOM、改行・引用符に対応しています。数式として読まれる先頭文字はExcel用だけ文字列化します。列と日時・IDの説明は隣の.columns.jsonに出します。

評価詳細・全訂正履歴のCSVは、row_typeで所見（annotation）、候補の実用性・採用（candidate）、候補間の比較（comparison）を区別します。絞り込んだ学習に関係する比較評価は、相手の候補も含めて出力します。単独LoRAはrun_id・artifact_id・強度・LBWの列、複数LoRAの構成はcomponents列で確認できます。

CSVはスナップショットです。Excelで変更しても台帳へ戻りません。Excelで開いていて書き込めない場合は、閉じるか別名で保存してください。

「AI相談用データ」では表示中の学習または選択中の学習から、次の一式をderivedに出します。

README.md、runs.csv、candidates.csv、comparisons.csv、reviews.jsonl、features.csv、feature_definitions.json、issues.csv、export_manifest.json。

まずREADME.mdとissues.csvを確認します。元ログのhash、run・評価の版、抽出コードのhash、使ったepoch、欠測の理由を含みます。

初期指標はloss・DQ・DQ auto・rank・avg・Scaleから20種類です。すべての学習で全項目が埋まるわけではありません。

- 名前だけで結び付けたログは既定で数値から除外します。必要なら、仮データと明示して含める設定を選べます。
- 早期checkpointには後のepochを混ぜません。同一runの別epochと、別run間の共通区間を区別します。
- DQのScope・Targetが不明なら数値の利用を制限します。指標版不明の数値には印を付け、版を確認した別run間の共通区間へ混ぜません。
- DQ autoにepochがない場合、全記録の件数は出せてもcheckpoint区間へ推定で割り当てません。
- 診断JSONしかない場合、定義を確認した勾配の配列を利用します。推定stepを正確なglobal stepとして扱いません。
- 記録の巻き戻り・重複・観測不足は理由を残します。画像数、ログ行数、checkpoint数を独立した学習回数にしません。

既存研究は「参照先の設定」の任意欄へ、data/files.csvとdata/epoch_metrics.csvがあるフォルダを指定します。source hashが一致する集計だけをlegacy.*の別定義で参照します。既存の大きなSQLiteや元ログは複製しません。既存研究がなくても動作します。

## 保存場所とバックアップ

コードはリポジトリ内、正本は外部台帳です。

```text
sd-scripts/
  lora_ledger_gui.py
  lora_ledger_gui.bat
  tools/lora_ledger.py
  tools/lora_ledger_core/
  .local/lora_ledger_gui.json     前回開いた台帳だけ。gitignore対象

lora_ledger/
  ledger.json                   参照先設定・台帳ID・版
  locations.local.json           参照元の場所
  runs/                          学習・設定・成果物の記録
  reviews/                       評価の全訂正版
  history/runs/                  登録情報の変更前
  research/                      自分やAIの分析成果
  cache/                         再生成できる走査キャッシュ
  exports/                       Excel用
  derived/                       AI相談用
```

バックアップは外部台帳フォルダ単位で取れます。cacheと再生成できる派生出力は除外できます。元ログ・重み・画像は別途保管してください。

複数の操作が同じ記録を変更した場合は版の競合を検知します。JSONは一時ファイルから置き換え、複数ファイルの保存中に中断した場合は次回の読込時にジャーナルから回復します。

## CLI

GUIと同じ処理を呼びます。以下のパスは架空の例です。--ledgerには作成済みの台帳フォルダを指定してください。

```powershell
.\venv\Scripts\python.exe tools/lora_ledger.py scan --ledger D:\lora-workspace\lora_ledger
.\venv\Scripts\python.exe tools/lora_ledger.py register --ledger D:\lora-workspace\lora_ledger
.\venv\Scripts\python.exe tools/lora_ledger.py verify --ledger D:\lora-workspace\lora_ledger --full --run-id <ID>
.\venv\Scripts\python.exe tools/lora_ledger.py export --ledger D:\lora-workspace\lora_ledger --run-id <ID>
```

--sourceは追加する探索フォルダです。登録から外したフォルダは保持している参照先IDを再利用して登録し、無効化した探索先は除外条件などを保って有効に戻します。registerは既定で新規と追加資料を反映し、変更・欠落は明示した--run-idまたはGUIで確認します。--fullは内容を全読込するため、全重みを対象にすると時間がかかります。

exportの--selectionには `{"run_ids": ["ID"], "include_unverified": false}` というJSONファイルを渡せます。学習後のbatへ追加する場合も同じregister処理を利用できます。既存の学習batや学習コードの変更は行っていません。

## 検証

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -p "test_lora_ledger*.py" -v
.\venv\Scripts\python.exe -m unittest discover -s tests -p test_training_settings.py -q
```

台帳・PySide6操作の65テスト、既存設定記録の27テストを確認しています。Qtテストはoffscreenで実行します。

走査時間はファイル数・保存先・キャッシュの状態によって変わります。通常の再走査ではキャッシュを利用し、内容hashの完全確認は必要な対象を選んで実行してください。

画像の好みの採点・研究仮説の検証は、人が評価を記録してから行います。ブラインド投票JSONの保存、新規dataset内容hash、重みテンソルの解析、全自動画質予測は初版の対象外です。

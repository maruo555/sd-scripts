# LoRA診断レポートの複数ラン比較：仕様案

状態：初期版を `tools/lora_comparison.html` に実装済み。操作方法は `docs/lora-comparison-viewer-ja.md` を参照。この文書には後続の検討事項も含む。

## 1. 基本方針

学習batに現在書かれている、学習後の単独レポート生成コマンドをそのまま使う。学習が終わるたびに、そのランの単独HTMLとJSONを従来どおり保存する。比較対象の指定や人の操作は、夜間処理には追加しない。

複数ランの比較は、別の共通HTML「比較ビューア」を入口とする。ユーザーが生成済みJSONを読み込むと、その場で比較画面を構成する。比較結果を残したい場合は、対象データと表示設定を含むHTMLとして保存する。

単独レポート、動的な比較、保存済みの比較を次のように位置付ける。

- 単独レポート：1ランの診断結果をいつでも確認する成果物。
- 比較ビューア：そのとき調べたい複数ランを選ぶ作業画面。
- 保存済み比較HTML：選んだランと比較状態を持ち運び、後から再確認する成果物。

「動的」は、ブラウザ内で対象の追加・差し替え・集計区間の変更ができるという意味とする。学習の監視、ログの自動追尾、サーバーへの接続は初期版に含めない。

## 2. 出力ファイルと役割

通常の出力先を例にすると、次の配置とする。

```text
diagnostic_report/
  lora_comparison.html          共通の比較ビューア
  run_A_diagnostic.html         Aの単独レポート
  run_A_diagnostic.json         Aの解析データ
  run_B_diagnostic.html         Bの単独レポート
  run_B_diagnostic.json         Bの解析データ
```

| ファイル | 内容 | 通常の開き方 |
|---|---|---|
| `*_diagnostic.html` | 1ランの診断結果と閲覧に必要なデータ | ダブルクリックして単独表示 |
| `*_diagnostic.json` | 1ランの解析データ。比較の正式な入力 | 比較ビューアの選択画面、またはドロップで読み込み |
| `lora_comparison.html` | 対象未選択の比較画面。特定のランに依存しない | ダブルクリックして比較を開始 |
| `compare_*.html` | 選択したランのデータと表示設定を内包する比較結果 | ダブルクリックすると保存時の比較を再表示 |

単独HTMLは、共通の比較ビューアや隣接JSONがなくても単独で閲覧できる現在の形を維持する。JSONを読み込むのは比較操作時であり、単独HTMLを開くためにJSONを別途読む構造には変えない。

## 3. 夜間batと比較ビューアの配布・更新

完成済みの1ファイルHTMLをsd-scriptsに同梱する。配置場所の案は `tools/lora_comparison.html`。そのまま開くことも、任意のフォルダへ手動コピーして使うこともできる。配置・更新用CLIは作らない。

JavaScript・CSS・必要なライブラリをHTMLに同梱し、Python、Node.js、サーバー、ネット接続を閲覧時に必要としない。JSONと同じフォルダに置く必要もない。コピー後、ランが何件増えてもHTMLの再生成は不要。

機能追加・不具合修正、または将来のJSON形式への対応が必要なときに、利用者が新しいHTMLをコピーし直す。画面にはビューアのバージョンを表示する。最新版の自動確認や自動更新は行わない。

更新しても、過去の単独HTML・JSONや保存済み比較HTMLは変更しない。保存済み比較HTMLは保存当時の画面コードを持つため、共通ビューアを更新しても自動では更新されない。

初期版の実装では、既存のPythonプログラム、JSON出力形式、単独HTMLの生成処理、夜間batを変更しない。単独HTMLへの入口リンク追加も初期版から外し、利用者が共通ビューアを直接開く。

## 4. 比較の入口

### 採用案：独立した比較ビューア

入口は同梱または手動コピーした `lora_comparison.html` とする。初期版では単独レポートにリンクや比較モードを追加しない。

独立させる理由は、単独診断の画面を簡潔に保ち、過去のJSONを新しい画面で比較できるため。比較対象はユーザーによるファイル選択・ドロップで読み込み、隣接JSONの自動読み込みには依存しない。

単独HTMLからの入口リンクや、現在のランを比較画面へ引き継ぐ機能は、必要になった段階で検討する。初期版の完成条件には含めない。

### 初期画面

- 「レポートJSONを選択」ボタン。複数選択に対応する。
- JSONのドロップ領域。
- 何も読み込んでいない間は空のグラフを並べない。
- 1件読み込んだらラン情報を表示し、追加対象の選択を案内する。
- 2件以上で比較画面を表示する。

## 5. 読み込むデータ

### 正式な入力は既存の診断JSON

初期版が受け付けるのは、単独HTMLと同時に出力される `*_diagnostic.json` とする。ファイル名だけでは判定せず、内容を検証する。

既存JSONには勾配、DQ、Rank、Group Loss、LoRA解析、epoch推移等が保存されている。現在のHTMLには表示整理後のデータを埋め込んでいるため、比較用のデータ源はJSONに統一する。原則として元の解析配列を計算に使う。過去の形式に対応するため、JSON内のchartsも読み込み、元配列の対応が不明な指標は収録されたグラフ値をそのまま表示する。元配列がない項目で、既存の移動平均からrawの区間平均を逆算する等は行わない。

比較ビューアはJSONをブラウザ内で読み込む。元のログ、safetensors、JSON中に記載されたパスを自動でたどらない。読み込んだJSONや単独HTMLを書き換えない。

### 旧レポートとの互換性

- schemaのバージョンがない既存JSONは、旧形式として読み込み変換する。
- 初期版ではJSON出力形式を変更しない。schemaバージョンの追加は後続案とし、既存JSONの読み込みを妨げない。
- 未対応の新しい形式は、黙って誤表示せず、ビューア更新が必要なことを示す。
- DQ等の項目がないランも読み込めるようにする。欠損をゼロやOFFに置き換えない。
- 一部ファイルが破損していても、他の正常なファイルの読み込みは継続する。
- ファイルの内容はデータとして扱う。HTMLやJavaScriptとして実行しない。

### 初期版で読み込まないもの

単独HTML、学習ログ、safetensors、学習bat、画像比較レポートを、そのまま入力する機能は初期版に含めない。HTMLを指定した場合は、対応する診断JSONを選ぶよう短く案内する。

元の詳細ログにしかない情報の追加は後続の別作業とする。その場合はPython側のレポート生成を拡張してJSONに収録する方法を検討する。初期版は既存JSONの範囲に限定し、JSONにない情報まで復元できるようには見せない。

## 6. 比較画面の操作

初期版は2〜4ランを同時に表示する仕様とする。多い場合は表示対象を選び、残りは候補一覧に保持する。

- 対象の追加、除外、差し替え。
- 基準ランの変更。
- Lossの重ね描きと基準との差。
- 全期間、後半、終盤、指定区間での比較。
- 表示範囲の系列ごとの有効記録数・平均・最小・最大・最終記録値。raw Loss以外を選んだ場合、その表示系列の集計とする。勾配超過数・率の専用集計は後続の検討事項。
- 元グラフの補足・Metric・Scopeと未収録項目の表示。全学習設定の差分表は初期版に含めない。
- 利用可能な指標だけを表示し、詳細グラフは展開する。

同じ内容のJSONを再追加した場合は重複を抑止する。同じラン名でも内容が異なる場合は上書きせず、生成日時等を添えて区別する。古いレポートには確実な実行IDがないため、名前だけで同一ランと断定しない。

途中終了や学習長の違いがある場合は、共通範囲を標準にする。共通範囲がない場合は、同一区間の差分を算出できないことを示す。表示上の補間から新しい観測値を作った扱いにせず、区間集計は実際の記録から行う。

設定情報が不足する旧JSONは、そのまま比較しつつ「未確認」を表示する。同じデータセットや評価条件であることを、名前や数値の近さから推定して確定しない。診断スコアやLossの大小から品質の勝者を自動決定しない。

## 7. 保存済み比較HTML

「比較をHTMLに保存」で、その時点の比較を一つのファイルにまとめる。

保存対象は次のとおり。

- 選択したランの比較に必要なデータと出典情報。
- 保存時に非表示だった期間も含む、対象ランの収録済み時系列。
- 基準ラン、対象の順序、比較区間、横軸、表示指標。
- データ形式・比較処理のバージョンと保存日時。
- 比較画面を再表示するためのコードと必要な表示資材。

保存したHTMLは、元JSONの場所に依存せず、オフラインで開けるものとする。元JSONを更新しても保存済み比較が勝手に変わらないよう、パスだけでなくデータ自体を保存する。

再表示後も、基準や区間の変更、別JSONの追加を可能にする。変更した結果は、改めて別の比較HTMLとして保存できる。

保存はブラウザのファイル保存操作を使う。生成フォルダへ自動で書き戻されるとは限らない。ファイル名の初期値は `compare_<比較名>_<日時>.html` 等とする。

元の単独HTMLやJSONを埋め込みページとして並べる方式にはしない。比較に必要なデータを一つの画面で共通の軸・集計方法により描画する。

## 8. 生成時に比較対象を指定する方式との関係

生成済みJSONを複数指定して比較HTMLを作るコマンドは、初期版には作らない。将来必要になれば追加を検討する。これは比較ビューアと別の製品ではなく、対象をあらかじめ読み込ませる入口と位置付ける。

Python側は入力JSONを検証して必要なデータを格納し、ブラウザ側の比較用データ変換・集計・描画を共用する。同じ入力と設定なら、ブラウザで選んだ場合とコマンドで作った場合の比較結果が一致することを要件とする。

通常の単独生成コマンドに比較相手の指定を必須にしない。夜間に毎回比較したい組み合わせが固まったときだけ、batへ比較生成を追加できる形にする。

## 9. 内部構成

役割を次の四つに分ける。

1. Pythonの単独解析・出力：既存の処理を変更せず、単独HTML・JSONを生成する。ビューアの配置・更新は手動コピーで行う。
2. 比較データ変換：旧／新JSONを共通の形式へ変換し、指標の有無・単位・定義を保持する。
3. 比較処理・画面：対象選択、軸合わせ、集計、差分、表示を担当する。
4. 比較の保存・再表示：比較データと画面設定を含むHTMLを作る。

比較画面のソースは同梱の完成済みHTMLを正として一か所で管理し、共通ビューア・保存済み比較・将来のコマンド生成で使い回す。Python内に同じHTMLやJavaScriptを別の文字列として保持しない。単独HTMLに後から比較モードを追加する場合も、このソースを再利用する。規模が増えてソースを分割する場合も、完成済みHTMLを配布に含め、利用者にビルドを要求しない。

保存済み比較のデータ・設定には専用のバージョンを持たせる。診断JSONへのschemaバージョン追加は後続案とし、初期版では現在のJSON形式をそのまま読み込む。

新しい比較ビューアは外部サーバーやCDNへの接続を必要としない構成とする。ライブラリ等が必要なら出力HTMLに同梱する。

## 10. 初期版の受け入れ条件

- 現在のbatと同じ単独生成コマンドで、従来のHTML・JSONが作られる。
- 比較対象を指定しなくても夜間処理が完了する。
- 同梱の共通ビューアを直接開く場合と手動コピーした場合で、同じ比較機能を利用できる。
- ビューアは初回配置後、ランを追加するたびに更新する必要がない。
- Pythonプログラム、夜間bat、JSON出力形式、単独HTMLの生成処理を変更せず利用できる。
- 過去の診断JSONを再生成せず、複数選択・ドロップで比較できる。
- 読み込んだファイルの元データを変更しない。
- 欠損、ゼロ、同名の別内容、異なる学習長、途中終了を区別できる。
- 同じ区間で表示系列の記録値を集計し、時間平均や画像品質の評価と区別する。率から新たな件数や時間割合を推測しない。
- 保存した比較HTMLを別フォルダへ移し、元JSONを参照できない状態でも再表示・区間変更できる。
- 保存済み比較に別JSONを追加し、再保存できる。
- 日本語・空白を含むパス、個別の出力先指定、ネットワークなしの環境で動作する。
- PCと狭い画面で、操作部とグラフが欠けない。

過去235件について、旧形式の読み込みと項目の有無を確認する。実際の画面検証は、詳細ログあり／なし、欠損あり、異なる長さ等の代表例で行う。

## 11. 実装順

1. 既存JSONを使う独立ビューアと共通の比較処理。
2. 比較状態のHTML保存と再表示。
3. 完成済みHTMLの同梱、手動コピーでの利用案内、既存JSONとオフライン動作の検証。
4. 後続案は別途検討し、初期版と一緒には実装しない。

1〜3を初期版の一まとまりとする。既存の単独レポートを夜間に作る運用を保ちながら、翌朝その場で比較し、判断に使った比較を保存できる状態を完成条件とする。


## 12. 以前の提案から分離する後続案

| 項目 | 既存プログラムへの変更 | 初期版での扱い |
|---|---|---|
| 配置・更新用CLI | 新規Pythonツール | 不要として取り消し |
| 単独HTMLから比較へのリンク・現在ランの引き継ぎ | 単独HTML生成処理の変更 | 見送り。ビューアを直接開く |
| JSON schemaバージョン・実行設定・出典情報の追加 | レポート生成処理。情報によっては学習側の記録も変更 | 別作業。未記録は未確認として表示 |
| 平均化の採用履歴、詳細なモジュール別Rank、Group Lossの追加列 | 元ログの読み込みとJSON出力の拡張 | 別作業。既存JSONにある値は利用可能 |
| 画像比較・投票結果の保存と連携 | 既存画像比較ツール等の変更 | 別作業 |
| 対象を指定して比較HTMLを作るコマンド | 新規Pythonツール等 | 必要になったら検討。ブラウザからのHTML保存は初期版に含む |

初期版の利用者向け実行ファイルはHTML一つとする。説明書、互換性・操作の検証用ファイルは開発成果物として追加できるが、利用者の環境で実行する前提にはしない。


## 13. 既存グラフを中心とした初期版の範囲

過去235件のJSONと生成コードの確認では、通常のグラフの元配列または描画値がJSONに保存されている。初期版は、これらの既存グラフを複数ランで比較することを中心にする。

対象：Loss、勾配・閾値、ThreshOff、Scale、Cosine、DQ各種指標、Rank集計・学習率・グループ推移、最終ヒートマップ、Group Loss、LoRA解析集計、収録済みの情報密度推移。

過去のJSONには現在の生成コードと異なる形式や追加項目もある。具体的にはDQ Direct、DQ Guard、Group Scale／Ratio、epoch単位のgradient alignment等が存在する。現在のコードのグラフID一覧だけで対象を限定せず、名称変更・項目構造の差を吸収する。指標定義やscopeが確認できないものは、無条件に同じ軸へ重ねず、まず並列表示する。

新規の解析データなしで追加できる表示には、基準との差、同一区間の集計、グループ重み量の絶対量と割合の対表示、Group Lossの収録済みepoch平均・件数などがある。

一方、平均化候補とrawの評価履歴、元Rankログの各モジュールの完全な時系列、完全な学習設定・データ同一性の記録、生成画像・投票結果は、別の情報源の取り込みが必要。Group Lossのtimestep・bucket・scale等の追加情報はJSONの世代によって収録状況が異なり、全て未収録とも全て収録済みとも扱わない。情報密度の推移は生成時に選択された系列の範囲を使い、省かれた系列を復元した扱いにしない。

初期版ではグラフ比較のために新しいログを要求しない。新規の分析アイデアは既存JSONで算出できるかを個別に確認し、追加データが必要なら後続の別作業とする。
